# ClickFlow

<p align="center"><img src="assets/icon.png" width="96" alt="ClickFlow 图标"></p>

ClickFlow 通过**图像匹配**在屏幕上找到图标，并按你定义的**顺序和等待时间**依次点击。它是通用工具，代码里没有任何针对某个网站或应用的逻辑；
自带的 `instagram_story_like` 配置只是一份数据（两个步骤：爱心、下一个箭头）。English: [README.md](README.md)

> **使用条款提醒**：自动点赞（或任何自动化操作）可能违反 Instagram 或其他服务的使用条款，并可能导致账号被限制或封禁。请**少量使用**、
> 设置较长且带随机性的延迟、并设置较小的**最大点击次数**。使用后果由你自己承担。
> ClickFlow 是独立项目，与 Instagram、Meta 或任何其他服务没有关联，也未获其认可。

## 下载（Windows 10 / 11，64 位）

在项目的 **Releases** 页面下载 **`ClickFlow.exe`**：单个文件，免安装，不需要 Python，双击即可运行。

* 首次运行会在 `C:\Users\你的用户名\ClickFlow\` 生成配置和日志，并创建默认配置。卸载 = 删除 exe 和这个文件夹。
* Windows 可能提示"未知发布者"（exe 没有代码签名）：点 *更多信息 → 仍要运行*。部分杀毒软件会误报所有 PyInstaller 单文件程序，
  可以核对 Releases 里 `ClickFlow.exe.sha256` 的校验值，或者自己从源码构建。
* 默认配置带两张示例模板图，但**搜索框是空的**：请在你自己的屏幕上为每个步骤画一个搜索框（见下面"快速开始"）。

## 功能

- 步骤列表：每步有模板图、匹配阈值、**搜索框**、点击偏移、点击类型（左键/右键/双击）、等待、超时和未找到时的处理（跳过/重试/停止/按备用键）
- **速度条**：一个滑块控制"从一次点击到下一次点击"的时间（最快无额外延迟，最慢 1.5 秒）；勾选"Advanced"可手动编辑每步等待
- **显示器预设**：按分辨率保存搜索框和模板，开始运行时按检测到的屏幕分辨率自动切换预设和显示器
- **Test this step**：只查找、不点击，明确告诉你"运行时会不会点击"；找不到时自动诊断原因（图标大小变了 / 在搜索框外 / 阈值偏严 / 屏幕上没有）并提供一键修复
- 试运行（Dry run，画框但不点击）、结束条件图像、点击总数上限、随机延迟抖动
- 随时停止：**F8**、屏幕上的红色 **STOP** 按钮、把鼠标移到屏幕任意一角
- 实时日志：每一步的相似度、位置、点击坐标

## 快速开始（Instagram 故事点赞示例）

1. 启动 ClickFlow，会打开 `instagram_story_like` 配置（顶部黄色提示栏有说明）。里面有两张作者屏幕上截取的**示例模板**，**搜索框为空**，
   因为图标大小、主题和显示缩放因机器而异。
2. 打开故事页面，让爱心和"下一个"箭头可见。
3. 选中一个步骤，点 **Test this step**。它会明确告诉你运行时**会不会**点击以及相似度。如果显示 NOT FOUND，看诊断信息（可点 *Apply suggested fix*），
   或点 **Capture template...**，在**你自己的屏幕**上拖框圈住图标，紧接着会让你拖**搜索框**。步骤 1 截取**未点赞的（空心）爱心**，步骤 2 截取**下一个箭头**。
4. 为每个步骤画好**搜索框**（*Draw search box...*）：比扫描整个屏幕快得多，也更可靠。
5. 点 **Dry run** 观察整个流程（画框但不点击）。
6. 点 **Start**。开始前有 2 秒切换到故事窗口。**F8**、红色 STOP 按钮、或把鼠标移到屏幕角落都能停止。

默认配置是最快速度、最多 500 次点击、无限循环，**实际使用请拖慢速度滑块并调小点击上限**。步骤 1 勾选了"只在找到时点击"，所以已经点过赞的故事
（实心爱心，匹配不到）会被直接跳过，不会白等。

不想碰真实应用时，可以先用自带的练习目标：`python -m clickflow.mock_window`（一个会统计点击次数的假故事查看器）。

## 速度

顶部的 **Speed** 条控制"一次点击到下一次点击"的时间，右端最快，左端 1.5 秒：

| 滑块 | 点击间隔 |
|---|---|
| 100%（最快） | 无额外延迟，由截屏+点击本身决定（约 0.25–0.3 秒） |
| 75% | 约 0.4 秒 |
| 50%（新配置默认） | 约 0.6 秒 |
| 25% | 约 1.0 秒 |
| 0%（最慢） | 1.5 秒 |

程序会测出自己截屏和点击的耗时并扣除，所以间隔就是你选的值。随机抖动（Randomness）仍然生效，所以这个数是平均值；要严格固定就把抖动设为 0。
勾选 **Advanced: edit waits manually** 后滑块失效，每个步骤用自己的 Wait before / Wait after。

## 搜索框与多显示器

整屏扫描很慢（单个 2560×1440 显示器约 0.8 秒，三屏约 2.3 秒），还可能匹配到别处的相似图标。**搜索框**把每个步骤限制在图标出现的区域内（约 55 毫秒，与屏幕大小无关）。
画一次，以后每次运行自动套用。截取模板后会直接接着让你拖搜索框；**Show boxes** 可以在屏幕上短暂显示所有框。

**显示器预设**保存某个分辨率下的搜索框（和可选的模板图）。框的位置相对于该显示器左上角，所以在系统里重新排列显示器也不会失效。
勾选 **Auto-switch by detected resolution** 后，开始运行时会检测当前连接的显示器，选择分辨率匹配的预设并**只截取那块显示器**；
如果两块显示器分辨率相同，会在每块上试找图标，选真正找到的那块。

## 常见问题："Test this step 画的框位置很准，但不点击"

只有匹配相似度达到**阈值**才会点击。Test 总是在"最佳候选位置"画框，哪怕相似度太低，所以框可能正好落在图标上而步骤仍是"未找到"。
现在日志会明确写出 `FOUND … A run WOULD click` 或 `NOT FOUND … A run would NOT click`，并自动给出诊断：

| 诊断 | 含义 | 一键修复 |
|---|---|---|
| 大小 | 图标在屏幕上，但比模板大/小很多（浏览器缩放、窗口大小或显示缩放变了） | 放宽缩放范围 |
| 搜索框 | 图标在屏幕上，但在搜索框之外 | 按它实际位置重画 |
| 阈值 | 有相似内容，相似度略低 | 降低阈值 |
| 不存在 | 屏幕上没有类似的东西 | 在图标可见时重新截取模板 |

默认搜索 0.35 倍到 2.5 倍的模板大小。

## 从源码运行 / 自己构建 exe

需要 Python 3.11+。Windows 运行 `run.bat`，macOS/Linux（X11）运行 `./run.sh`。构建单文件 exe：

```
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python build_exe.py
```

输出 `dist\ClickFlow.exe`，随后会运行它内置的自检（`ClickFlow.exe --selftest 报告.txt`）。macOS 需要在"系统设置 → 隐私与安全性"里授予
*屏幕录制*和*辅助功能*权限；Linux 需要 X11 会话（Wayland 不支持）。macOS / Linux 版本没有经过测试。
